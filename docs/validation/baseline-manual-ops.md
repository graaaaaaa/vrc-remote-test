## 数え方

人の操作は、次の1つずつを1回と数えます。待つだけの時間は数えません。

| 記号 | 種別 | 例 |
|---|---|---|
| K | コマンド1行の入力（シェル、PowerShell、SQL） | `vrcrt.sh export-log 0 <dir>`、`Stop-Process -Id <PID>` |
| P | 画面上のクリック・キー操作1回（Unity、VRChat、エクスプローラー） | Remote Build & Test、タブレットの［救済を求める］ |
| S | 別の機械・画面・端末への切り替え1回 | Mac から Windows（Moonlight など）へ、端末から Unity へ |
| R | 値を目で読んで写すこと1回 | PID、buildId、runId、slot、export のフォルダー名 |
| J | 合否・メモの入力1回 | 判定の結果を validation の記録に書く |

- 1行のコマンドを打ち間違えて打ち直したら、2回と数え、メモに「打ち直し」と書きます。
- 道具やエージェントが代わりに行った操作は数えず、「誰が」の欄に `道具` か `エージェント` と書きます（人がエージェントに頼む文を打った場合は K を1回）。
- 1つの手順の中でまとめて押す操作（例: 2台でそれぞれ［救済に同意］）は、押した数だけ数えます。

## 時間の決まり

- 時刻は JST で、秒まで書きます。成果物（export のフォルダー名、`run.json`、ログの時刻）があれば照らします。
- **始め**: 人がその件のために最初の操作をした時刻。
- **材料がそろった**: 判定に使うログや証拠がすべて Mac にそろった時刻（export が終わった時刻）。
- **判定が出た**: 判定のスクリプトが結果を出した時刻（手で判定するなら、人が合否を決めた時刻）。
- **手を動かした時間**: 各手順の「人の始め〜人の終わり」を足したもの。待ち（Bridge の起動、40秒の待ち、目印を待つ間）は入れません。

### A・B への当てはめ

- **A（救済と、持ち主の退出・途中参加）**
  - R1b で人の手から外せるのは A7〜A10 で、`close-client <slot> --expect` と `launch-client <slot> --expect` の2行になる。外れるのは、PID を調べる、`Stop-Process`、`Start-Process`、引数を写すことで、K3 R2 にあたる。40秒の待ちも要らない（退出の確認は 5 s、起動し直しの準備は 9 s）。
  - 救済の4回のクリック（A3〜A5）と Windows の画面への切り替え（S1）は残る。人の操作は 10 回から 5 回になる（受け渡しを除く）。
  - **leave-rejoin の固定の手順は、A にそのままは使えない。** leave-rejoin は配備から退出まで間を置かずに進むが、A では配備と退出のあいだに、人が救済を押す段がある。Commander の `dice_life_auto` と同じく、自分の流れの中から前提つきの close／launch を呼ぶ形になる（§5.4 の「前の run を参照する入口は作らない」の決まりのため）。
  - 持ち主の slot を決めるのは Commander の目印（`--target-slot` に渡す）。どう決めたかは基準の記録にも無い。
- **B（2台の配備と判定）**
  - もともと人の操作が0回で、Commander の `prt001_deploy_run.py` が1行で配備と書き出しをしている。R1a で変わるのは、配備の結果の判定（`deploy-result.json`）、台の準備の判定、証拠のハッシュを道具が持つことで、エージェントの手順の数は変わらない（B3〜B4 の1行が runner の1行に代わるだけ。推定）。
  - 時間の大半（約11分）は、ワールドの試験が `OPS_PROBE step=done` を出すまでの待ちで、道具では縮まない。deploy-collect は「試験の終わり」の目印を待たないので、終わったあとの書き出し（B6〜B7）は今と同じく別に要る。

## 気づいたこと

- R1 で減ったのは、PID を調べて閉じて起動し直す手（A）と、配備の結果と台の準備を読むこと（B）。人に残るのは、ゲームの中のクリック（A の救済の4回）と、画面の切り替えになった。
- 試験の途中に人の段がある件（A）は、固定の手順では回せない。R3（手作業の試験の準備と記録。「次に押すものの表示」「押した時刻の目印」）は、ここをつなぐ。R5（デスクトップ入力）の調べは、A の4回のクリックが減らせるかを決める。
- 試験の終わりの目印を待ってから書き出す段（B5〜B7）は、どの件にもある。deploy-collect に「この目印が出るまで待ってから回収する」を足すと、B の流れを1回の run にできる（候補。目印から対象やパスは作らない）。
