# Phase 0.5 — `--watch-worlds` 検証スパイク

**目的**: VRC Remote Testの中核前提「VRChatが `--watch-worlds` 付きで起動中に、Worldsディレクトリへ `.vrcw` を配置すればリロードする」を実機で検証する。

**位置づけ**: 使い捨てのスパイクである。Bridge実装（Phase 1完了済み）を経由せず、手動でファイル配置を模擬して核心的な問いにのみ答える。Phase 2（Unity Core実装）を開始する前提条件。

**関連レビュー**: `[removed]/codex-plan-review-state/` — 3ラウンドの反復深化Codexレビューを経てスコープを最小化。

---

## 前提条件

以下がWindows実機・Mac開発機の双方で準備できていること。

- [ ] Windows 11マシンにSteam + VRChatがインストール済み
- [ ] Windows側にPowerShell 7（`pwsh`）がインストール済み
- [ ] macOS側でALCOMを使いUnity VRChat Worldsプロジェクトを作成済み
- [ ] VRChat SDK Control Panelから `Build()` を1回実行し、有効な `.vrcw` を取得済み（ビルドターゲット: `StandaloneWindows64`）
- [ ] （推奨）視覚的に区別できる2つのWorldビルドがある（例: 空のシーンと、目立つ色のオブジェクトを置いたシーン）— リロードを目視で確実に判別するため
- [ ] 取得した `.vrcw` をWindows側の作業ディレクトリ（例: `C:\VRCRemoteTest\spike\`）へ手動でコピー済み（SMB転送はPhase 2の検証対象であり、本スパイクの対象外）

Worldsディレクトリの既定パス:
```
%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\Worlds
```

---

## 使用スクリプト

- `scripts/start-vrchat-dev.ps1` — VRChatを検証用引数で起動
- `scripts/deploy-test.ps1` — `.vrcw` をWorldsディレクトリへatomicにデプロイ（Bridgeを介さない手動模擬）

両スクリプトの詳細はスクリプト内のコメントを参照。

---

## リロード確認方法

- **一次確認（必須）**: VRChatの画面を直接観察し、Worldが切り替わったことを目視確認する。2つの視覚的に区別できるビルドを交互に配置すると判別しやすい。
- **補助確認（任意）**: VRChatの `output_log_*.txt`（`%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\` 内、最新のもの）を開き、World読み込みに関連するログ行がないか確認する。ログの正確なフォーマットはクライアントバージョンに依存するため、事前に決め打ちせず、実際に出力された内容を確認して結果記録に転記する。

Udonマーカーの埋め込みなど、能動的な計装は本スパイクでは行わない（過剰な準備コストのため）。

## 必須テストケース（3件 — Go/No-Go ゲート）

以下3件は必ず実施する。1つでも想定外の結果が出た場合、Go/No-Go判定テーブル（下記）に従って評価する。

### ケース1: 初回配置 → リロード確認

1. `scripts/start-vrchat-dev.ps1 -Mode Desktop` でVRChatを起動（`--watch-worlds` あり）
2. VRChatの起動完了（ホーム画面到達）を待つ
3. `scripts/deploy-test.ps1 -SourcePath <build1>.vrcw` で1つ目のビルドを配置
4. VRChatの画面を観察し、Worldがロードされるか確認
5. リロードが起きるまでの概算時間を記録

### ケース2: 2回目の配置 → 再リロード確認

1. ケース1のVRChatプロセスを起動したまま
2. `scripts/deploy-test.ps1 -SourcePath <build2>.vrcw`（ユニークなファイル名）で2つ目のビルドを配置
3. 再度リロードされるか確認（可能なら視覚的に異なるビルドを使う）
4. リロードが起きるまでの概算時間を記録

### ケース3: ネガティブベースライン

1. VRChatを終了し、`scripts/start-vrchat-dev.ps1 -Mode Desktop -NoWatchWorlds` で `--watch-worlds` **なし** で再起動
2. `scripts/deploy-test.ps1 -SourcePath <build1>.vrcw` で同じ手順で配置
3. リロードされ **ない** ことを確認（一定時間、例えば60秒待って変化がないことを確認）
4. もしリロードされてしまった場合、ケース1・2の結果は `--watch-worlds` に起因すると言い切れない — スパイク自体の前提が汚染されている

## オプションテスト（必須ゲート通過後のみ実施）

必須3ケースが全て期待通りの結果になった場合のみ、余力があれば以下を追加検証する。省略しても Phase 2 開始判断は可能。

- [ ] atomic rename（`.tmp` → `.vrcw`）経由でのリロード確認（`deploy-test.ps1` は既定でこの経路を通るため、実質ケース1・2で検証済み）
- [ ] 5回連続ユニークファイル名デプロイ（安定性確認）
- [ ] 大容量ファイル（50MB+）でのデプロイ・リロード確認
- [ ] Rapid rebuild（10秒間隔で連続配置）
- [ ] 同名ファイルへの上書き配置時の挙動
